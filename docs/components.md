# Как собрать экран из библиотеки

### Атомы

У атома одна визуальная или интерактивная роль, которую можно использовать в нескольких сценариях. Имя и свойства описывают сам элемент. Например, `Icon` получает имя пиктограммы и роль цвета, `Button` получает подпись и обработчик. Они ничего не знают о разговоре, модели устройства или сетевом запросе.

Для нового атома укажите имя экспорта и типизированные свойства. Опишите назначение, варианты, применимые состояния и профиль устройства. Покажите каждое заявленное состояние живым элементом с подписью. Для фокуса используйте нативный `:focus-visible` и проверьте его клавишей Tab. Кнопке с одной иконкой требуется доступное имя, состоянию связи — текст или различимый знак. Предпочитайте нативные семантические элементы, сохраняйте фокус клавиатуры и проверяйте крайние значения. Для профиля BOX контролируйте область касания в окне 320 × 240.

### Составные блоки

Если элемент объединяет несколько ролей, сначала соберите его из существующих атомов. Например, `VolumeControl` состоит из подписи, иконки звука, двух иконочных кнопок и индикатора уровня. Он получает значение и вызывает `onChange`. В метаданных блока перечислите фактические зависимости в `uses`. Каталог показывает ссылки на эти части.

### Полные экраны

В проекте, который потребляет библиотеку, соберите экран как TSX-композицию. Импортируйте переиспользуемые элементы по имени пакета. Семантические области страницы, компоновка и иллюстрации могут принадлежать экрану. Сетевые данные, маршрут, значения и подтверждение действия контролирует потребитель. Аватар — сменный контент устройства.

```tsx
import { useState } from 'react';
import { NetworkRow, Stack, VolumeControl } from '@nearic/ui-box';
import '@nearic/ui-box/styles.css';

export function SoundSettings() {
  const [volume, setVolume] = useState(60);
  return <Stack data-family="box">
    <NetworkRow online value="Домашняя" />
    <VolumeControl value={volume} onChange={setVolume} />
  </Stack>;
}
```

### Порядок изменения

1. Найдите существующий атом, вариант или составной блок. При смене цвета темы или размера касания сначала проверьте [токены](tokens.md).
2. Для новой роли опишите задачу, состояния и критерии приёмки в доменной спеке. Добавьте типизированный экспорт, стили на общих токенах и живой образец со статусом «Предложение».
3. Покажите отдельно образец и продуктовый экран на целевом дисплее. После решения владельца зафиксируйте принятую версию.
4. При ревью сопоставьте интерактивные элементы экрана с экспортами пакета, проверьте отключённые состояния, доступные имена и клавиатуру. Изменение библиотечного компонента должно быть видно в обоих потребителях после обычной сборки.

Разделение цветовых и типографических токенов, каталога иконок и базовых контролов можно посмотреть в [Plasma](https://github.com/salute-developers/plasma/tree/dev/packages).
