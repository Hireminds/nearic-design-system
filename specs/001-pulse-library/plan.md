# Сборка витрины и Storybook

Каждый компонент хранит реализацию и связанные материалы в собственной папке пакета. Индекс пакета сохраняет импорт по его публичному имени. Реальные CSS-модули собираются вместе с прежними стилями для потребителей. Card предоставляет поверхность блокам настройки.

Storybook и сборка витрины читают истории из папок компонентов. CI рендерит основной пример и варианты каждого компонента в HTML с CSS пакета. Для каждого компонента генерируется отдельная страница с навигацией и ссылками на истории. Это сохраняет размер начальной загрузки при расширении библиотеки.

В браузере модуль выбранного компонента активирует основной пример. Обработчики, декораторы, вложенные элементы и взаимодействие с аргументами берутся из истории. Аргументы основного примера и панели обновляются вместе. Прямые ссылки, прежние адреса с якорем, конструктор и технический Storybook сохраняют свои точки входа.

Генератор читает типы TypeScript, находит свойства и ключи переводов. Настройки истории уточняют тип контрола и доступные варианты конкретного примера. Словари проходят проверку на совпадение ключей. Приватный Web потребляет инструменты документации как зависимость разработки.

Проверка охватывает типы, сборку и установку архивов в отдельный проект, целостность словарей и источников историй, ссылки между витриной и Storybook, управление в обе стороны и доступность на узком экране.

Для каждой страницы проверяются HTML при отключённом JavaScript, соответствие образцов и ссылок индексу Storybook, активация основного примера и доступные варианты. Для управляемых элементов проверяют оба направления изменения значения. Время появления оформленного примера и первого редактирования сравнивают при одинаковой холодной загрузке в мобильном профиле браузера.
